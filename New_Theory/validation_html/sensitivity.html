Menos graus de liberdade efetivos = mais robustez — mas a contagem honesta importa: 89 campos ≠ 89 DOF.

Propostas de redução (fundamentadas no estudo)

  1. Merge estrutural K_archard/hardness ⇒ k_wear_spec = K/H [1/Pa]. Os dois só aparecem como razão (wear e fretting) — não-identificáveis separadamente. −1 variável, zero custo, remove uma equifinalidade exata.
  2. Estágio B: remover a camada de tuners (≡1.0). −9 variáveis (roadmap #8, spec 2026-07-02 §3; shim p/ .msd legados). Já congelados — a remoção é higiene de API que impede regressão a fits por multiplicador.
  3. Congelar os "congeláveis" do tornado (badges verdes): fixar no nominal e retirar de qualquer rotina de fit/registro de candidatos (parameter_registry) — DOF nominal → 0 sem mudança de predição mensurável.
  4. Ler em vez de fitar (converter DOF em proveniência): emb ← queda-inicial (feito no axial, L24: 12 condições, −90% erro); floor ← fim do dado (feito); delta_free ← regressão de onset (feito no Liu2025). Restante: c_bend é o único knob transversal sem leitura conhecida (§4.41) — alvo de instrumentação futura (medir compliance da fixação), não de fit.
  5. Capabilities inertes (48 campos) não são DOF — cada uma liga SÓ com falsificação dupla + gate (doutrina). Higiene proposta p/ Estágio B: movê-las a um bloco forms separado do núcleo, deixando o dataclass principal com ~21 campos físicos.
  6. Dinâmica (rayleigh/m/I) fora de JointMaterial — são parâmetros de solver, não de material; não afetam a trajetória de pré-carga.
